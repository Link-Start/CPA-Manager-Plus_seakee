# 系统信息

系统信息页面用于确认当前面板连接到什么运行时、可用哪些模型，以及排障时应提供哪些基础信息。

日志内容请看 [日志查看](./logs.md)。请求、成本和账号状态请分别看 [请求监控](./monitoring.md)、[用量分析](./usage-analytics.md) 和 [认证文件](./auth-files.md)。

## 主要内容

- **运行时管理**：页面顶部展示部署模式、CPAMP/CPA 当前版本、可用更新、发布说明、更新进度、失败原因和回滚结果。
- **快速链接**：打开主仓库、Web UI 仓库和文档入口。
- **模型列表**：从当前连接读取可用模型，并按来源分组展示。
- **登录存储清理**：清除浏览器里保存的登录连接信息。
- **连接状态**：用于判断当前是否已经连接到可用 CPA 或 Manager Server。

实际显示内容会随使用方式变化。CPAMP 轻量面板连接 CPA，完整模式连接 Manager Server；完整模式可以通过 Docker 或原生包安装。在线演示只显示虚构数据，不属于可连接真实服务的运行模式。

## 更新入口和层级

仪表盘继续保留轻量的版本检测和徽标。内置 CPA 的 Integrated/Full 部署以签名 runtime manifest 作为徽标与“查看更新”的唯一依据，避免公开 Release 版本与当前平台可安装版本产生矛盾；外部和分离式部署继续使用公开版本检测。当发现可安装的 CPAMP 或 CPA 更新时，点击“查看更新”进入系统页顶部的运行时管理面板。

系统页负责完整流程：

1. 检查签名 runtime manifest，并分别展示 CPAMP 与 CPA 的当前/目标版本。
2. 查看各组件发布说明后选择更新。
3. 通过任务进度查看下载、校验、安装、健康检查和切换状态。
4. 失败时展示原因以及自动回滚是否成功；Manager 重启期间仍可使用操作令牌查询任务。

只有内置 CPA 的 Integrated/Full 部署允许托管更新。Slim 下载 CPA 成功后会转为 Integrated；外部 CPA 和安装器管理的分离部署只显示当前模式，不提供更新按钮。

## 动态 Base Path

运行时管理面板可以把前端入口动态改为 `/`、`/admin`、`/panel` 等安全绝对路径。保存成功后新路径立即生效，旧路径返回 404；API 保留路径、路径穿越、查询参数和片段会被拒绝。

如果 `CPA_MANAGER_PANEL_BASE_PATH` 由环境变量设置，UI 只读显示，必须修改部署环境并重启。Base Path 只能降低入口可发现性，不能替代 TLS、强管理密钥、防火墙或访问控制。

## 模型列表怎么用

模型列表适合回答两个问题：

1. 当前运行时能看到哪些模型。
2. 模型是来自哪个提供商或配置。

如果客户端请求某个模型失败，先在这里确认模型是否可见；如果不可见，再去 [AI 提供商](./ai-providers.md) 检查配置和模型规则。

模型可见不代表请求一定成功。认证、配额、上游状态和路由规则仍然可能导致请求失败。

## 清除登录存储

清除登录存储会删除浏览器里保存的面板连接信息，适合这些情况：

- 切换到另一个 CPAMP 或 CPA 地址。
- 管理员密钥变更后，浏览器一直使用旧连接。
- 本地开发或演示环境之间来回切换。

这不会删除服务器上的配置、认证文件、SQLite 数据或 CPA 配置。它只影响当前浏览器。

## 排障时建议提供

反馈问题前，先在系统信息页确认并记录：

- CPAMP 版本和运行模式。
- CPA 版本。
- 当前连接目标：CPA、Manager Server 或本地开发服务。
- 模型列表是否能正常加载。
- 是否刚清理过登录存储或更换过地址。

再结合 [日志查看](./logs.md) 和 [请求监控](./monitoring.md) 提供同一时间段的脱敏证据。
